What changed
------------
At -O0 the a and b loops exist as real loops. Every one of the 9 taps runs a separate copy of
the loop-control code (increment, compare, branch), and every row of 3 taps also resets b and
increments/tests a.

-O0, b loop and a loop control (lines 590-592, 636-649):

    .L45:
    str     wzr, [sp, 108]      // b = 0
    b       .L43
    ...
    ldr     w0, [sp, 108]       // b++
    add     w0, w0, 1
    str     w0, [sp, 108]
    .L43:
    ldr     w0, [sp, 108]       // b < 3 ?
    cmp     w0, 2
    ble     .L44
    ldr     w0, [sp, 112]       // a++
    add     w0, w0, 1
    str     w0, [sp, 112]
    .L42:
    ldr     w0, [sp, 112]       // a < 3 ?
    cmp     w0, 2
    ble     .L45

At -O3 both trip counts are the constant 3, so the compiler unrolls them completely. The body
of the column loop (.L60) is one straight run of 9 pixel loads and 18 multiply/accumulates
with no inner branches. The only branch per pixel is the column-loop test at the bottom.

-O3, all nine taps in one block (lines 471-515, pixel loads only, with their row/column):

    ldrb    w7, [x21, 1]        // above[c]
    ldrb    w9, [x21]           // above[c-1]
    ldrb    w8, [x21, 2]        // above[c+1]
    ldrb    w11, [x23]          // current[c-1]
    ldrb    w10, [x23, 1]       // current[c]
    ldrb    w9, [x23, 2]        // current[c+1]
    ldrb    w8, [x22]           // below[c-1]
    ldrb    w11, [x22, 1]       // below[c]
    ldrb    w10, [x22, 2]       // below[c+1]
    ...
    cmp     x21, x25            // the only loop test left (line 534)
    bne     .L60

Each of the 9 (a, b) positions became a fixed immediate offset ([x21, 2], [x22, 1], ...), so
the window[a] lookup and the c + b - 1 index math disappear too (see
part_2_MC_strength_reduction.txt).

How it helps performance
------------------------
-O0 runs 9 b-loop tests and 3 a-loop tests (plus their loads/stores of a and b) for every
output pixel: about 24 + 9 x 6 = 78 instructions per pixel just for control. Unrolling
removes all of them and 12 taken/not-taken branches per pixel. It also gives the scheduler
one large block of independent loads and multiplies to interleave (see
part_2_MC_instruction_scheduling.txt).
